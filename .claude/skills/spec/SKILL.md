# 仕様書作成スキル

$ARGUMENTS について仕様書を作成してください。

## 手順

1. `backend/src/routes/` と `frontend/src/` の関連コードを Glob と Grep で調査して既存実装を把握する
2. `docs/specs/` ディレクトリに以下の形式で仕様書を作成する
3. 仕様書のファイル名は `docs/specs/<feature-kebab-case>.md` とする
4. 作成後、「仕様書を作成しました。内容を確認してOKであれば実装に進みます」と報告する

## 仕様書テンプレート

```markdown
# [機能名] 仕様書

作成日: [今日の日付]
ステータス: 草案

## 概要
[機能の概要を1〜3文で説明]

## 背景・目的
[なぜこの機能が必要か]

## スコープ

### 対象
- [含まれる機能]

### 対象外
- [含まれない機能]

## 機能要件
[番号付きリストで要件を記述]

## 非機能要件
- パフォーマンス要件:
- セキュリティ要件:
- アクセス権限:

## UI/UX
[画面フローや操作方法]

## API設計（Zod OpenAPI）

### エンドポイント一覧
| メソッド | パス | 説明 |
|---|---|---|
| GET | /api/xxx | [説明] |

### Zodスキーマ定義（案）
[リクエスト・レスポンスのZodスキーマ例]

### 生成されるAPIクライアント（orval）
- `useGetXxx()` — 一覧取得
- `useCreateXxx()` — 作成

## 実装上の注意点
- Cloudflare Workers の制約:
- スキーマ変更後は `bun run generate:api` で再生成が必要

## 完了条件
- [ ] `bun run check` でエラーなし
- [ ] Scalar UIでエンドポイントが確認できる
- [ ] フロントエンドから正しくデータの取得・更新ができる
```
